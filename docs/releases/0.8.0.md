## Behaviour covered

The macro-stepper integration opens current-line, selected-form, and whole-module
buffers through the public `macro-debugger/stepper` API. Installed tests disable
the language server while checking compile-time markers, so a background
language-server expansion cannot satisfy the command test. They verify dirty
and untitled buffers, relative macro imports, source lines, no implicit save,
no module runtime effects, and independent terminal lifetimes. GUI tests inspect
an actual expansion window, advance its display, and cancel a stuck transformer
and its child process on Linux.

Rhombus acceptance uses real `.rhm` documents and the packaged language client.
It checks definitions, source hovers, tokenisation, unsaved diagnostics and
repair, comment toggling, language-server restart and disable/enable, and
protection against applying the Racket formatter to Rhombus source. The existing
Racket editor, debugger, REPL, and package checks also pass with Rhombus installed.

Test Explorer checks execute the real repository suites in both profiles, stop
at a breakpoint with a live local, report an intentionally failed assertion and
its source location, rerun after correction, and evaluate repeatedly through the
four-file Debug REPL example.

The new editor integration, grammar, and tests were independently implemented
from public documentation. The upstream macro expansion engine remains an
identified dependency. See [editor tools](../editor-tools.md) for the behavioural
specification sources and [publisher identity](../publishing.md) for the
distinction between the author and Marketplace publisher display name.

The loader regressions also cover a forwarding load handler requiring a compiled
sibling submodule from a foreign namespace, synchronous and threaded expansion,
and nested loaders with different compilation policies across continuation
prompts. The same tests fail against the original handler-identity check and an
intermediate prompt-sensitive ownership implementation, and pass with the shared
dynamic owner parameter. Worker startup initialises that parameter before
starting debuggee threads. These checks leave both instrumentation files unchanged.

See the [stepping walkthrough](../stepping.md) for the initial stop at function
creation and the distinction between expression entry and returned values.

## Reproduce

With full Racket, locked npm dependencies, Python 3, VS Code, and Xvfb available:

```sh
node scripts/package-extension.js
node scripts/test-headless.js
python3 tests/harness-checks.py
python3 scripts/test-gui.py
python3 scripts/test-vscode.py --artifact dist/racketeer-0.8.0.vsix --timeout 1200
python3 scripts/test-vscode.py --rhombus --artifact dist/racketeer-0.8.0.vsix --timeout 1200
python3 scripts/test-vscode.py --dogfood --artifact dist/racketeer-0.8.0.vsix --timeout 1200
PLTCOLLECTS="$PWD/vendor/collects:" raco test vendor/collects/racket-langserver/tests/lib/doc-test.rkt vendor/collects/racket-langserver/tests/lsp/watched-create-test.rkt
node scripts/artifact.js verify dist/racketeer-0.8.0.vsix
```

Pass `--code` and `--xvfb` where required. The Rhombus run requires network access
for the pinned packages. Run installed-editor modes sequentially. A rebuild may
have different archive timestamps; record and test its own artifact identity.

## Boundaries

Rhombus editing requires its language package in the selected Racket installation.
The lexical grammar is not a complete shrubbery parser; its group-comment,
custom at-text delimiter, and emoji boundaries are documented in the editor
guide. Rhombus formatting, source debugging, Debug REPL, and Test Explorer
compatibility are not claimed by these checks.

Macro fragments expand in a fresh namespace; use the whole-file command for
enclosing module imports and macros. A full graphical Racket installation is
required. Expansion can execute compile-time code. Unix process ownership and
Windows process-tree limitations remain as recorded in the quality requirements.

Windows/macOS installed-editor workflows, remote development, network failure
scenarios, and sustained resource/performance measurements remain outstanding
production validation. These local results do not establish those configurations.

An earlier macOS/Racket 9.3 CI attempt intermittently failed to load an upstream
`old-cond` submodule. An unchanged rerun passed the native language tests. The
forwarding-loader regression above demonstrates a separate controlled failure;
it does not establish the cause of that intermittent CI result. Failed macOS
headless jobs now retain fresh-process language-load diagnostics for follow-up.
