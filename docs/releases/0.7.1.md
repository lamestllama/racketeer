## Corrections covered

- Instrumentation preserves nested continuation-mark behavior; ephemeron
  associations allow completed target namespaces to be collected.
- A separate live process-group owner cleans ordinary worker descendants after
  worker or adapter failure on Unix. Startup and the complete handshake have a
  cancellable total deadline. A terminated session cannot be relaunched.
- Captured source comes from the same bytes used to load the program. Source
  selection consults current breakpoints. Breakpoint configuration is validated
  atomically and location queries respect line and column bounds.
- Language-server initialization can be cancelled, restarted, or disposed while
  blocked. The configurable startup deadline defaults to 180 seconds to allow
  cold compilation. Owned transport endpoints close before waiting for process
  cleanup.
- Delayed watched-file creation preserves an already-open language-server
  document, its text, and its version. Subsequent incremental edits remain valid.
  Both synchronization regressions fail before the correction and pass afterward.
- Selection evaluation works inside a paused outer interaction. Captured source
  belongs to one debug session. Pending launches retain cancellation ownership
  until they settle. Action context updates occur only when needed.
- Protocol failures remain visible through teardown. Headless test discovery is
  shared by npm and workspace tasks. Packaging uses the locked local packager;
  installed checks reject stale artifacts and exclude checkout caches.

The pinned Microsoft language-client SDK has a documented one-line source
correction to preserve its startup promise when the connection closes during
initialization. The build checks the dependency version and original/patched
source hashes; the MIT notice is preserved. See [vendor notes](../../vendor/README.md).
Pinned upstream archive reproduction and both Racket source patches were also
verified in an isolated mirror; the SDK patch applies separately during npm/build.
The installed checks cancel an actual unresponsive server, restore its executable,
verify recovery, and assert that no unhandled rejection occurs.

Test Explorer validation also stops inside a real repository test, inspects a
live local, checks a deliberate failed assertion and its source location,
restores the assertion and reruns it, then repeats Debug REPL calls through four
nested source files. Only disposable workspaces are edited.

## Reproduce

With full Racket, Node.js 20+, Python 3, VS Code and Xvfb available:

```sh
npm ci --prefix vscode
npm_config_offline=true node scripts/package-extension.js
node scripts/test-headless.js
python3 scripts/test-gui.py
python3 scripts/test-vscode.py --artifact dist/racketeer-0.7.1.vsix
python3 scripts/test-vscode.py --dogfood --artifact dist/racketeer-0.7.1.vsix
PLTCOLLECTS="$PWD/vendor/collects:" raco test vendor/collects/racket-langserver/tests/lib/doc-test.rkt
PLTCOLLECTS="$PWD/vendor/collects:" raco test vendor/collects/racket-langserver/tests/lsp/watched-create-test.rkt
node scripts/artifact.js verify dist/racketeer-0.7.1.vsix
```

Pass `--code` and `--xvfb` when required. These editor runs used `--timeout 1200`
to allow cold starts on a busy host; individual assertion deadlines were unchanged.
Run editor checks sequentially to avoid competing cold compilation workloads.
Every run still has its own fresh state.
A rebuild may have different archive timestamps; record its own hash and run the
installed checks against that artifact before distributing it.

## Remaining production work

Windows, macOS, Linux x64, a supported version matrix, remote development,
network package failure cases, and long-session/resource measurements still
need validation. Windows currently terminates the immediate worker and needs
native process-tree ownership before equivalent cleanup can be claimed.
Processes that deliberately leave the owned Unix group are outside that group's
cleanup. Test Explorer reports files rather than discovering individual cases;
Test Package delegates package metadata policy to the native runner. The language
client selects one Racket installation per editor window.

Cross-language control transfer to other debuggers is not implemented.
See [the debugger feature matrix](../parity/DEBUGGER.md) for semantic boundaries.
