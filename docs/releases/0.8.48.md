# Racketeer 0.8.48 validation

Date: 2026-11-01 (Australia/Adelaide). Development release. These results cover
the recorded local environment; the other platforms and editor versions require
successful results from the [CI matrix](../ci.md).

## Contents

- Continuous integration corrections. Build outputs that differ from their
  input only in case are the same file on Windows and macOS. Coverage records
  visits without constructing debugger stops. Run File and Start Debug REPL
  keep the source editor active after opening Interactions. The workspace index
  tests are split by feature, platform-specific tests state their platform, the
  Pause cancellation test judges by message order, installed-editor stages log
  their durations, and the core and installed-editor jobs have budgets for
  their current suites.
- racket-langserver at upstream `b7c4642` with three upstream pull requests
  (UTF-16 positions, open-buffer imports and relative imports without a
  directory, #246 to #248) as submitted and two local patches, which replace
  the five earlier ones, and vscode-languageclient 11.0.0 with vscode-jsonrpc
  10.0.0, which replace both client patches. VS Code 1.91 or newer is required.
  A request whose analysis failed or passed its deadline fails with
  `RequestFailed`, as upstream answers.
- Untitled documents follow upstream. An associated save location is their
  only import base; definitions, references and rename stay within the
  document; the workspace index covers saved files only. A relative import in
  an untitled document without a save location reports that one is required,
  instead of resolving against the language server's working directory.
- Cooperative attachment to a Racket program that loads
  `racketdap/worker/attach.rkt` (API 1); see the
  [embedding host contract](../../racketdap/instrumentation/DESIGN.md#embedding-host-contract).
  A file the host's loader selects keeps that loader's bytecode policy when the
  host itself runs under the debugger, so the attach suite also passes through
  Test Explorer.

## Workspace references under editor activity

Before release, the debugging stage in VS Code 1.91.0 waited without end for
references from a captured source. VS Code closes documents that an extension
opened once they have gone unused for a while, and during that stage it closed
one every 2 to 15 seconds. Each close cancelled the workspace index's pass in
progress and started it again from the first file, and a reference request
waits for a complete pass, so it was answered only when the closes paused for
longer than a whole pass (about 100 seconds here). Every editor version and
the 0.8.47 suite were exposed; the stage took over five minutes wherever it
passed.

A revision that only opens or closes documents over unchanged sources now
keeps the current analysis: a pass in progress or a partial index continues,
and a complete index is verified against the disk in place. A waiting request
checks its document against each revision, so reopening a document still
retires it at once.
