# Racketeer 0.8.50 validation

Date: 2026-11-03 (Australia/Adelaide). Development release. These results cover
the recorded local environment; the other platforms and editor versions require
successful results from the [CI matrix](../ci.md).

## Contents

- The debugger is compiled once for each Racket version and VM into the extension's
  storage, in the background after the first launch begins. A small program goes
  from launch to exit in about 0.85 s instead of about 2.8 s. The compiled debugger
  notes each library it was compiled against, and runs from source when one changes.
- Instrumented code is kept in the extension's storage between debug sessions and
  reused while the hashes of each source and of everything it depends on match.
  `racketdap.debug.compiledCache` and the `debugCache` launch attribute turn it off.
- Long function bodies load in close to linear time, and a place the debugger could
  stop costs two reads and a store until something needs it to stop there. `fib(30)`
  runs under the debugger in about 0.1 s instead of 48 s. Frames locate themselves by
  their site instead of holding a copy of their syntax.
- A debug worker that ends before its program finishes, while loading or
  running, names its exit code or signal in the Debug Console and the session
  ends. Signal 9 is described as the way the system ends a process that runs out
  of memory.
- A breakpoint on a line whose code comes from a macro in another file that
  drops the line's source location is verified on that line and stops there.
- A breakpoint stops, and Step In enters a dependency, when a path names the file
  differently from the program, through a symbolic link or, where the file system
  ignores case, in another case. A relative `program` is relative to its `cwd` or the
  workspace folder.
- Variables lists a binding a macro makes when the source refers to it, a row named
  `this` in a class's methods and initialisers, and a row for each class field a
  method's code reads or assigns. A scope returns every row instead of the first 100,
  and a container reports its size, so VS Code pages a long one.
- Step Out with no function to leave finishes the evaluation around the stop. Generated
  code no longer adds stops or breakpoint hits at a source expression that has its own
  stops. An operation around a constant or variable can still stop at that text, but
  shows no value the text did not return. A range counts as covered only if the code
  written there ran.
- A Racket older than 9.1 is named with its version and path on Run, Debug, Test
  Explorer, the language server and the workspace index, which do not start on it.
- racket-langserver at upstream `b7c4642` with three upstream pull requests
  (#246 at `b1916ed`, #247 at `f0606dc`, #248) and four local patches. Columns are
  counted in UTF-16 after tabs and in CRLF documents, a column past the end of a line
  means the end of that line, and a cancelled analysis worker cannot leave the server
  blocked on state it shared.
- The language server waits 250 ms after the last edit of a document before analysing
  it, and a request a person makes starts it at once.
  `racket-langserver.analysisWaitMilliseconds` changes the wait.
- The workspace index is a standalone server that speaks standard LSP. It runs only
  when Find All References or Rename asks, and a pass analyses again only the files
  whose text or dependencies changed. Each file is analysed in a process of its own,
  up to three at once and no more than half the processors, and the answers are the
  same as one worker's. Each worker has a 2 GiB limit on what its analysis adds to
  its libraries.
- The formatter that indents by the rules of a file's own language is the value
  `language` of the two formatter settings.
- A test debugs a third-party program of about a thousand lines, fetched at a
  pinned commit and hash.

## Limits

- Windows has no status-change time, so a library replaced there with the same size
  and date goes unseen by the compiled debugger.
- Each extra index worker adds about 260 MB while a pass runs, and compile-time code in
  different files can run at the same moment. Validating a rename still takes one worker.
- A macro that reads a file it does not register sees that file only at the next change
  to a file loaded with it, after Refresh Workspace References, or after a restart.
- Diagnostics appear 250 ms later than without the wait when nothing asks first.
